# Изменения за 10-08-2026

## Исправлено

- Всплывающее окно аварии теперь остаётся отображаться после возврата измерения в допустимый диапазон.
- Возврат значения в норму отключает звуковой сигнал, но не выполняет квитирование.
- Окно закрывается только после явного нажатия кнопки «Квитировать».
- Правка выполнена в общем коде и применяется одинаково к профилям `FULL` и `LIGHT`.

- `arduino-cli compile --fqbn esp32:esp32:esp32 .` для `LIGHT` после временного переключения `ACTIVE_PROFILE`: код собирается, но итоговая прошивка также не помещается во flash (`1528604` байт при лимите `1310720`).
- `python -m unittest -v tools.test_logic_scheme`: не выполнен, модуль `tools` отсутствует в рабочем дереве.
- `python -m unittest -v tools.test_logic_full_matrix`: не выполнен, модуль `tools` отсутствует в рабочем дереве.

## Версия

- `1.7.8` -> `1.7.9`

## Перенос источников embedded Web UI

- Источники frontend, необходимые для генерации embedded Web UI, перенесены из промежуточного каталога `OUT` в поддерживаемый каталог исходников.
- Добавлен и документирован воспроизводимый механизм генерации embedded headers.
- После проверки зависимостей удалены подтверждённые промежуточные копии из `OUT`.
- Embedded Web UI и gzip-ресурсы сохранены.
- Логика аварий, звукового сигнала и квитирования не изменялась.
- Правка общая для `FULL` и `LIGHT`.

## Задержка тревоги при потере датчиков температуры и давления

- Для `T1`, `T2`, `T3` и `P` добавлена задержка публикации тревоги при потере датчика.
- Добавлены compile-time параметры `TEMP_SENSOR_LOSS_DELAY_MS` и `PRESSURE_SENSOR_LOSS_DELAY_MS`.
- Значение по умолчанию составляет 3000 мс.
- Raw fault сохраняется немедленным для текущей реакции управления.
- Кратковременная потеря до истечения задержки не публикуется пользователю как sensor-loss тревога.
- Устойчивая потеря после истечения задержки проходит через существующие alarm/UI/sound/ack пути.
- Существующая sticky-логика неподтверждённой тревоги сохранена.
- Поведение `dT`, `L`, `F` и других датчиков не изменялось.
- NVS, `SensorBlob` и миграции не изменялись.
- Правка выполнена в общем коде для `FULL` и `LIGHT`.

### Проверки

- `arduino-cli compile --fqbn esp32:esp32:esp32 .` для `FULL`: код компилируется и доходит до финальной size-check, но итоговая прошивка не помещается во flash (`1529236` байт при лимите `1310720`).
- `arduino-cli compile --fqbn esp32:esp32:esp32 .` для `LIGHT` после временного переключения `ACTIVE_PROFILE`: код компилируется и доходит до финальной size-check, но итоговая прошивка также не помещается во flash (`1529008` байт при лимите `1310720`).
- `python -m unittest discover -v`: выполнен, автоматические host/unit-тесты в рабочем дереве не найдены (`Ran 0 tests`, `NO TESTS RAN`).
